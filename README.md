# Progress-Monitoring-System
## 1. 核心工作流程（先统一这个）
plain
## 工作流程
```text
管理员上传任务 → 员工接受任务 → 员工开始工作 →
员工提交成果（视频或报告）→ 管理员审核 →
   ├─ 通过 → 解锁下一环节 → 进度条前进
   └─ 驳回 → 管理员提交错误报告 →
        员工修改 → 重新提交 → 管理员再次审核
```
关键规则：必须上一个环节通过审核，才能解锁下一个环节。 这就是进度条的逻辑基础。
## 2. 角色与功能
管理员（Manager）
- 上传任务，并把任务拆分成有编号的环节/里程碑
- 审核员工提交的内容（视频或 PDF/报告文件）
- 通过 → 或者驳回并附上错误报告（逐条列出所有错误）
- 查看整体进度面板
员工（Employee）
- 查看分配到的任务和当前环节
- 上传工作成果：视频或报告（文件上传）
- 查看管理员的错误报告，修改后重新提交
- 查看个人进度条

## 4. 数据库（大约 5 张表）
- Users（id、姓名、角色：manager/employee）
- Jobs（id、标题、描述、创建人）
- Sections（id、job_id、环节编号、标题、状态：locked/in_progress/submitted/approved/rejected）
- Submissions（id、section_id、提交人、文件链接、文件类型：video/report、提交时间）
- Reviews（id、submission_id、审核人、结果：通过/驳回、错误报告、审核时间）
Sections 的状态字段就是驱动进度条的核心：
进度 % = 已通过环节数 ÷ 总环节数 × 100
## 5. 进度条
简单的计算公式：每个任务 = 已通过环节数 / 总环节数。员工端显示"第 3 个环节，共 8 个 — 37%"，管理员端可以看到所有员工的进度条。
## 6. 文件上传
- 接受 .mp4, .mov, .webm（视频）和 .pdf, .docx（报告）
- 文件存在硬盘或云存储（AWS S3 / Firebase Storage），数据库里只存路径/链接
- 设置文件大小上限（比如视频 100MB）
## 7. 两人分工建议
- A 同学： 后端——数据库、登录认证、任务/环节创建、提交与审核逻辑、文件处理
- B 同学： 前端——仪表盘、进度条、上传表单、审核页面
开发顺序：
1. 登录 + 角色权限 → 2. 任务和环节上传 → 3. 成果提交 → 4. 审核通过/驳回 + 错误报告 → 5. 进度条 → 6. 优化（通知、邮件等）
如果时间允许，值得加的附加功能： 审核结果邮件/站内通知、每个环节的提交历史记录、每个环节的截止时间。
## 8. 内容修改与优化
- 管理员的身份换成组长，而另外额外新增审核员与经理，审核员负责监督员工与组长是否有在工作，若没有可有按钮催促组长或者员工该项目的进行，他们将会收到通知，并且也有权增删人员（员工、组长），最后经理的身份权限是最大的，经理能够与组长一样发布与审核任务的权限，审核为大部分任务经过组长审核后最后轮到经理，同时也需要监督大家是否在工作，同时他也拥有权限增删改人员（员工、组长、审核员），当员工上传，组长经过审核通过后，已完成的工作内容最后都会到经理那儿，经理能查看所有工作内容。
- 同时发布工作时，新增可选择需要经过的人，比如上传的工作内容是否需要经过组长/经理，可以只选择到组长就完成，但最后所有完成的工作内容经理都能查看。
- 员工与组长需要分类部门，比如媒体部门、财政部门、旅游部、展会部门等等，每一个部门的进度条可以根据颜色区分，部门之间的组长与员工以及工作内容需要分开互不干涉看不到，只有审核员与经理能够看到全部部门，并且审核员或者经理新增人员的账号（名字、密码），同时把这账号分类好部门，员工或者组长使用这账号登入时直接进入该部门的界面
- 公司名字为北京中凰国际旅游社
- 增加登入界面密码可以选择可视或者不可视
- 经理和审核员的人员管理这儿，只需要保留其中一个新增人员的按钮，不需要两个在同一个界面，经理人员管理界面不需要发布工作按钮
- 工作总览界面的平均完成进度，平均完成进度这一栏的“按已通过环节计算”句子与数字进度百分比相撞了，或许空间上可以再隔开多一点
- 查看使用指南那一项直接删掉，直接单独新增一项在账号设置下面，名字为“使用手册”，里头根据账号分开记录员工、组长、审核员与经理如何使用该平台
- 账号设置里的内容目前暂时可设置更改头像照片与更改密码，点击右上角的圆形头像也可直接跳转账号设置
- 除了经理，员工、组长、审核员都有评分，初始分数为100分，每个月刷新一次分数，唯有经理有权限更改分数，若有员工工作超过了截止日期未完成将会自动扣除5分，接着以一天扣1分来计算，被审核也扣分，只要超过截止日期未完成都会扣
- 经理可在人员管理更改分数（增加或减少），这是为了给人员工作能力评分
- 每个月刷新一次分数，但经理可以通过人员管理查看每一位人员最多6个月前的历史评分
- 除了截止时间，也需要加上完成时间，若超过截止日期需要知道何时完成，完成时间为进度100%时记录该日期
- 使用手册不需要记录所有人员，根据账号来分辨，若用户为经理，则使用手册为经理的使用手册，若为审核员则为其使用手册，根据账号类别分开使用手册的内容
- 人员管理界面可增加筛选与搜索栏，筛选为身份与所属部门，搜索可找名字
- 任务看板界面可以筛选完成日期，经理与审核员则可多选择筛选部门
- 发布的工作内容若需要经理审核的，同样需要显示在经理账户的经理审核界面
- 组长与经理发布任务后也能继续编辑以及发布的任务，可更改截止日期、修改工作内容，修改负责的员工，亦或者取消任务的发布
- 人员管理的编辑、评分管理等等可以放在本月评分的右侧
- 密码的可视与不可视图标作用放反了，闭眼为不可见，睁眼为可见
- 审核顺序有经理，但在经理审核界面中却没有，发布工作需要谁审批若有选择组长/经理都需要同步到组长/经理审核，照片上显示已完成的工作内容有经过经理的审核，但是经理审核中的已完成却没有这个工作内容
- 审核的功能可以美化，与整个界面风格不一致（字体、颜色等等都不一致），包括身份、所属部门、日期等筛选，可参考图片上我的范围这个风格，并且筛选完成日期不需要多少日期至多少日期，完成日期只有一个，筛选什么时候完成的日期
